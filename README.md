# PyTorch Asynchronous ML Inference Serving

A production-inspired FastAPI + PyTorch **single-process** inference service with asynchronous workers, request microbatching, bounded queues, stable/canary routing, and metrics. The training dataset is synthetic; the two deployment variants initially use identical weights.

## Setup and run

```bash
python -m pip install -r requirements.txt
python training/train.py
PYTHONPATH=. pytest -q tests
PYTHONPATH=. python benchmarks/load.py --requests 600 --concurrency 32
uvicorn app.server:app --host 127.0.0.1 --port 8000
```

Model weights are generated by the training script and deliberately not committed.

## API

- `POST /predict`: `{"features": [0.2, ...]}` (32 numbers)
- `GET /health`
- `GET /metrics`
- `GET /metrics/prometheus`

## Benchmark

`results/load.json` contains recorded **in-process ASGI** load-test results, not network or multi-node throughput. Re-run before representing them as your own.

## Limitations

Workers are asyncio tasks in one process, not separately deployed nodes. No integrated C++ custom operator, GPU deployment, model-quality canary evaluation, or production alerting is claimed.
